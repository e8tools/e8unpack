# v8Unpack 3.0.50

Модули объектов, менеджеров и наборов записей теперь называются так, как их называет сама
1С, а модули форм вынесены в отдельные файлы рядом с формой.

## Что было не так

- **Модули лежали под номерами.** Внутри объекта все его модули попадали в один каталог с
  числовым суффиксом члена контейнера: `Документ1.0.bsl`, `Документ1.2.bsl`,
  `Справочник1.0.bsl`, `Справочник1.3.bsl`. По имени файла нельзя было понять, где модуль
  объекта, а где модуль менеджера, — приходилось запоминать таблицу суффиксов, а она у
  каждого типа своя: у документа модуль менеджера `.2`, у справочника `.3`, у плана
  обмена `.3` при модуле объекта `.2`, у регистра бухгалтерии модуль набора записей `.6`,
  а у плана счетов модуль объекта вообще `.14`.
- **Модуль формы хранился внутри файла описания формы.** Правка одной строки кода формы
  меняла большой служебный файл с `{4, …}`-описанием и BOM; диффы и история такой формы
  были нечитаемы.
- **Формы части типов попадали в служебный каталог `Конфигурация/`.** В таблице секций
  контейнера были прописаны не все: у документа, отчётов, обработок, перечислений,
  журналов документов, планов счетов, планов видов характеристик и видов расчёта,
  регистров (сведений, накопления, расчёта, бухгалтерии), бизнес-процессов и задач своя
  секция «Формы» с отдельным GUID. Пока его не знаешь, форма не привязывается к своему
  объекту и вместе со своим модулем оказывается в `Конфигурация/` под именем
  `Модуль формы <GUID>.bsl`.

## Что сделано

- **Модули объектов, менеджеров и наборов записей называются по роли.** Таблица «тип
  объекта + номер члена» → имя модуля: `Модуль объекта.bsl`, `Модуль менеджера.bsl`,
  `Модуль набора записей.bsl` (регистры), `Модуль бота.bsl`. Покрыты константы,
  справочники, документы, отчёты, обработки, журналы документов, перечисления, планы
  обмена, планы счетов, планы видов характеристик и видов расчёта, критерии отбора,
  хранилища настроек, регистры сведений, накопления, расчёта и бухгалтерии, задачи,
  бизнес-процессы, боты, а также модули самой конфигурации (`Модуль сеанса.bsl`,
  `Модуль обычного приложения.bsl`, `Модуль управляемого приложения.bsl`,
  `Модуль внешнего соединения.bsl`). Роли сняты не по памяти, а по подписям в самих
  модулях и проверены на двух объектах каждого типа.
- **Модуль формы вынесен в отдельный файл** `Модуль формы.bsl` рядом с описанием формы.
  Если в одном каталоге оказываются две формы (служебные формы конфигурации), имена
  разводятся по GUID описания — раньше второй модуль затирал первый.
- **BOM больше не теряется.** Модуль формы — текст 1С с BOM, а `QString::fromUtf8` его
  отбрасывает. Теперь признак BOM определяется по сырым байтам до среза и восстанавливается
  при обратной сборке; без этого контейнер расходился с исходным ровно на 3 байта за форму.
- **Новый разборщик текста 1С** (`src/core/OneCText.*`) — выделяет строку модуля из описания
  формы с учётом удвоенных кавычек внутри строк.
- **Манифест `.e8unpack/manifest.json` версии 2** с полем `formModule`, которое запоминает,
  что модуль вынесен из описания формы. Манифест версии 1 читается по-прежнему, старые
  распакованные деревья собираются.
- **Таблица секций «Формы»** дополнена 12 GUID-ами: документы, отчёты, обработки,
  перечисления, журналы документов, планы счетов, планы видов характеристик, планы видов
  расчёта, регистры сведений, накопления, расчёта и бухгалтерии, бизнес-процессы, задачи.

Как выглядит дерево теперь:

    Документы/Документ1/Модуль объекта.bsl
    Документы/Документ1/Модуль менеджера.bsl
    Документы/Документ1/Формы/ФормаДокумента/Модуль формы.bsl
    Регистры сведений/РегистрСведений1/Модуль набора записей.bsl
    Регистры сведений/РегистрСведений1/Модуль менеджера.bsl

## Что пока не вошло

Модули команд (`<Объект>/Команды/<Команда>/КомандаN.bsl`) и модули HTTP-сервисов,
Web-сервисов, WebSocket-клиентов и сервисов интеграции по-прежнему называются по имени:
в самих модулях нет подписи с ролью, а официальные названия этих модулей в разных версиях
платформы отличаются. Имена для них появятся в следующих выпусках.

## Совместимость

- Содержимое собранного контейнера не зависит от раскладки: упаковка из дерева даёт тот же
  файл `.cf`, что и раньше. Меняются только имена и расположение файлов `.bsl`.
- Распакованные ранее деревья (манифест версии 1) собираются без изменений.
- Если ваш скрипт опирался на имена вида `Документ1.0.bsl`, их нужно поправить на имена по
  роли.

## Проверено

- **Побайтовое совпадение с эталонной сборкой** (сборка из дерева старой раскладки) на
  четырёх конфигурациях: `1Cv8_mn.cf` → `f13eb062…`, `1Cv8_common.cf` → `d07244cf…`,
  `1Cv8_sp.cf` → `f6972219…`, `1Cv8_mods.cf` (403 члена, все типы модулей) → `5f035387…`.
- Список членов контейнера после сборки совпадает с исходным, ни один член не потерян и не
  добавлен; обратная распаковка собранного файла даёт дерево, идентичное исходному.
- На `1Cv8_mods.cf` в дереве 163 файла `.bsl` вместо 117 в старой раскладке: 46 модулей форм
  и 21 каталог `Формы/`; в служебном каталоге `Конфигурация/` остались только четыре модуля
  самой конфигурации.
- Штатные тесты `test/run.sh` и `test/run-cyrillic.sh` проходят.

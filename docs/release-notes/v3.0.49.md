# v8Unpack 3.0.49

Linux-сборка стала самодостаточной: Qt6 и её зависимости лежат в архиве рядом с бинарником,
и на машине пользователя не нужно ничего доустанавливать.

## Что было не так

Архив `v8unpack-3.0.48-linux-x86_64.tar.gz` содержал только бинарник, а он линкуется
динамически с Qt6 и ещё десятком библиотек. На машине без Qt6 (например, Astra Linux) это
выглядело так:

    ./v8unpack: error while loading shared libraries: libQt6Core.so.6:
    cannot open shared object file: No such file or directory

Хуже того, сборка шла на `ubuntu-24.04`, где glibc 2.39 и GCC 13: бинарник требовал
`GLIBC_2.38` и `GLIBCXX_3.4.32`, которых на дистрибутивах постарше просто нет — даже с
установленным Qt6 он бы упал на версиях символов.

## Что сделано

- **Сборка перенесена в контейнер Debian 12** (glibc 2.36, GCC 12, Qt 6.4). Требования к
  системе пользователя понизились: хватит glibc 2.36 и новее (Astra Linux 1.8, Debian 12,
  Ubuntu 22.04 и новее). Бинарник теперь требует максимум `GLIBC_2.34`
  (было `GLIBC_2.38`) и `GLIBCXX_3.4.29` (было `GLIBCXX_3.4.32`).
- **Совместимость со старым Boost.** В Debian 12 Boost 1.74, и у
  `boost::filesystem::directory_entry` там нет перегрузок с `error_code` — они появились в
  более новых версиях Boost. Перебор каталогов переведён на свободные функции
  `fs::is_regular_file(path, ec)`, которые есть во всех поддерживаемых версиях.
- **Несистемные библиотеки собираются в архив рядом с бинарником.** Замыкание обходится
  рекурсивно по `ldd` от самого бинарника: Qt6Core, ICU, glib, pcre2, zstd, zlib,
  double-conversion, libb2, libstdc++, libgcc, libgomp — всё в подкаталог `lib/`.
  Библиотеки glibc и динамический линкер не копируются: они есть в любой системе.
- **Прописан rpath, и именно RPATH, а не RUNPATH.** `RUNPATH` не наследуется
  зависимостями: бинарник нашёл бы в `lib/` библиотеку Qt6Core, а та уже не искала бы там
  свои ICU, glib и pcre2 — и на машине без системного Qt6 программа падала бы на
  `libicui18n.so.72`. Поэтому линковка идёт с `DT_RPATH` (наследуется по всей цепочке), а
  каждая скопированная библиотека дополнительно получает свой `$ORIGIN`. Значение:
  `$ORIGIN/lib:$ORIGIN/../lib/v8unpack` — второе для установки из `.deb`.
- **Сборка падает, если зависимость не нашлась или оказалась вне архива** — неполный архив
  не должен доезжать до пользователя. Проверка идёт без `LD_LIBRARY_PATH`, то есть ровно
  так, как будет работать на машине пользователя.
- **`.deb` тоже самодостаточен**: те же библиотеки ставятся в `/usr/lib/v8unpack`.

Размер архива вырос с 0,3 МБ до ~19 МБ — в основном за счёт ICU, которую тянет Qt6.

## Про «полностью статическую сборку»

Полностью статический бинарник без единой внешней библиотеки для Qt-программы на Linux не
получается: Qt6 статически собирается только из исходников (это часы сборки, свой набор
целей в CI), а glibc всё равно остаётся динамической — статическая glibc ломает загрузку
локальных модулей и локалей. Практический результат — «ничего не нужно доустанавливать» —
даёт именно этот вариант: один архив, внутри бинарник и все библиотеки.

## Проверено

- **Чистая система.** Архив распакован в Debian 12, где нет ни одной библиотеки Qt6:
  бинарник запускается, печатает версию и делает полный проход «упаковать → распаковать»
  с кириллическими именами файлов и каталогов — содержимое совпадает.
- **Разница между RPATH и RUNPATH** проверена на том же чистом Debian 12: с `RUNPATH`
  программа падает на `libicui18n.so.72`, с RPATH работает.
- Замыкание зависимостей архива: ни одной зависимости вне каталога (проверка проходит без
  `LD_LIBRARY_PATH`).
- Бинарник из распакованного архива и из `.deb` (распакован `dpkg-deb -x`) запускается.
- Тесты `test/run.sh` и `test/run-cyrillic.sh` прогоняются в том же контейнере Debian 12.

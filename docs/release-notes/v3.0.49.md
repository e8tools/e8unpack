# v8Unpack 3.0.49

Linux-сборка стала самодостаточной: Qt6 и её зависимости лежат в архиве рядом с бинарником,
и на машине пользователя не нужно ничего доустанавливать.

## Что было не так

Архив `v8unpack-3.0.48-linux-x86_64.tar.gz` содержал только бинарник, а он линкуется
динамически с Qt6 и ещё десятком библиотек. На машине без Qt6 (например, Astra Linux) это
выглядело так:

    ./v8unpack: error while loading shared libraries: libQt6Core.so.6:
    cannot open shared object file: No such file or directory

Хуже того, сборка шла на `ubuntu-24.04`, где glibc 2.39 и GCC 13: бинарник требовал
`GLIBC_2.38` и `GLIBCXX_3.4.32`, которых на дистрибутивах постарше просто нет — даже с
установленным Qt6 он бы упал на версиях символов.

## Что сделано

- **Сборка перенесена в контейнер Debian 12** (glibc 2.36, GCC 12, Qt 6.4). Это понижает
  требования к системе пользователя: хватит glibc 2.36 и новее (Astra Linux 1.8, Debian 12,
  Ubuntu 22.04+ и новее).
- **Несистемные библиотеки собираются в архив рядом с бинарником.** Замыкание обходится
  рекурсивно по `ldd` от самого бинарника: Qt6Core, ICU, glib, pcre2, zstd, zlib,
  double-conversion, libb2, libstdc++, libgcc, libgomp — всё в подкаталог `lib/`.
  Библиотеки glibc и динамический линкер не копируются: они есть в любой системе.
- **Бинарнику проставлен `RPATH`**: `$ORIGIN/lib` (распакованный архив) и
  `$ORIGIN/../lib/v8unpack` (установка из `.deb`). То есть Qt6 берётся из архива, а не из системы.
- **Сборка падает, если зависимость не нашлась** — неполный архив не должен доезжать до
  пользователя. Тот же скрипт проверяет готовый архив (`--check`): проходит по всем ELF в
  каталоге и убеждается, что каждая несистемная библиотека разрешается внутри каталога.
- **`.deb` тоже самодостаточен**: те же библиотеки ставятся в `/usr/lib/v8unpack`.

Размер архива вырос с 0,3 МБ до ~19 МБ — в основном за счёт ICU, которую тянет Qt6.

## Про «полностью статическую сборку»

Полностью статический бинарник без единой внешней библиотеки для Qt-программы на Linux не
получается: Qt6 статически собирается только из исходников (это часы сборки, свой набор
целей в CI), а glibc всё равно остаётся динамической — статическая glibc ломает загрузку
локальных модулей и локалей. Практический результат — «ничего не нужно доустанавливать» —
даёт именно этот вариант: один архив, внутри бинарник и все библиотеки.

## Проверено

- Замыкание зависимостей архива: проверка `--check` проходит (15 ELF-файлов, ни одной
  зависимости вне каталога).
- Бинарник из распакованного архива запускается и печатает версию; то же для `.deb`
  (распакован `dpkg-deb -x`).
- Запуск через динамический линкер с единственным путём поиска — `lib/` из архива:
  `ld-linux-x86-64.so.2 --library-path <архив>/lib v8unpack -V` работает, то есть системный
  Qt6 не используется.
- Тесты `test/run.sh` и `test/run-cyrillic.sh` прогоняются в том же контейнере Debian 12.

## Файлы

- `v8unpack-3.0.49-linux-x86_64.tar.gz` — Linux x86_64, с библиотеками внутри (распаковать
  и запускать `./v8unpack`)
- `v8unpack_3.0.49_amd64.deb` — пакет Debian/Ubuntu, библиотеки ставятся в `/usr/lib/v8unpack`
- `v8unpack-3.0.49-win64.zip` — Windows x64, всё нужное внутри (без изменений)

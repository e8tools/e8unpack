# v8Unpack 3.0.53

Расширения конфигурации (`.cfe`) раскладываются в дерево так же, как конфигурации (`.cf`).

## Расширения: дерево с именами объектов и каталогами типов

- **Было:** в контейнере расширения нет члена `root`, поэтому карта метаданных не загружалась.
  Имена объектов оставались GUID-именами, все файлы складывались в каталог `Конфигурация`,
  а модули, получившие одинаковое имя-заглушку, терялись — из 23 модулей в дерево попадал один.
- **Стало:** документ структуры расширения ищется по ссылке `{2,<guid>,<base64>}` в члене
  `configinfo` — это тот же узел, что и в `root` у конфигурации. Дальше раскладка идёт общим
  кодом: каталоги типов, имена объектов, роли модулей.
- Примеры из дерева расширения:
  - `Общие/Общие модули/РасшСКЛ_ОбщегоНазначения/Модуль.bsl`
  - `Документы/СпецификацияПроекта/Формы/ФормаДокумента/Модуль формы.bsl`
  - предопределённые данные элемента справочника лежат внутри каталога своего объекта:
    `Справочники/<Имя справочника>/<GUID>.1c`

## Обратите внимание

- Деревья `-DE` для `.cfe` изменились: вместо плоского каталога `Конфигурация` с GUID-именами
  теперь каталоги типов с именами объектов. Если ваши скрипты опираются на прежние имена, их
  нужно поправить.
- Сборка (`-CO`) не менялась: манифест хранит исходные имена элементов контейнера, поэтому
  расширение собирается как прежде. Формат манифеста не менялся.
- Разбор `.cf` не менялся: прежний путь остаётся эталоном для регресса.

## Что проверено

- Расширение 1,9 МБ (351 член): дерево разложено по каталогам типов, вынесено 56 модулей вместо 24,
  предупреждений о неопределённом корне и совпадениях имён модулей больше нет.
- Цикл распаковка → сборка → контрольная распаковка: список членов 351 = 351, деревья совпадают
  полностью (0 расхождений).
- Правка модуля в дереве доходит до собранного контейнера.
- Собранное расширение загружено в Конфигуратор 1С: **не отличается от исходного** (приёмка).
- Регресс на `1Cv8_mods.cf` (403 члена): sha256 сборки `5f035387…` совпадает с эталоном,
  макеты (`.mxl`) на месте.

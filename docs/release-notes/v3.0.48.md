# v8Unpack 3.0.48

Распаковка: элементы метаданных больше не сваливаются в служебный каталог `Конфигурация`.

## Что было не так

В `Конфигурация/` попадали формы, интерфейсы и обработчики команд — на реальной
конфигурации это ~45 файлов из 214. Причин оказалось три, и они независимы:

1. **Группы метаданных, объявленные, но не добавленные в карту типов.** Константы
   `GUID_Interfaces`, `GUID_Numerators`, `GUID_Sequences` существовали, но в карту их не
   вставили — объекты этих групп («Интерфейсы», нумераторы, последовательности) не
   опознавались и уходили в служебный каталог.
2. **У секции «Формы» свой GUID для каждого типа объекта.** В таблице секций был только
   «справочный» GUID, поэтому формы планов обмена, хранилищ настроек и критериев отбора
   вообще не индексировались. Соответствующие секции установлены по реальным данным.
3. **Обработчики команд ссылаются только идентификационным узлом.** У модуля команды
   (`<GUID>.2`) нет ни списка секции, ни отдельного файла — он упомянут лишь узлом
   `{1,0,<GUID>},"<Имя>"` в тексте владельца. Добавлен второй проход индексации: владелец
   и имя ищутся по текстам объектов метаданных.

## Как теперь выглядит раскладка

    Общие/Интерфейсы/Интерфейс1/<GUID>                                 (+ <GUID>.0)
    Общие/Планы обмена/ПланОбменаОсновной/Формы/ФормаСписка/<GUID>     (+ <GUID>.0)
    Общие/Планы обмена/ПланОбменаОсновной/Команды/Команда1/Команда1.bsl
    Общие/Планы обмена/ПланОбменаОсновной/Макеты/Макет1/<GUID>

- Элементы раскладываются по владельцу: `<Тип>/<Имя объекта>/<Секция>/<Имя элемента>/`.
- Формы, макеты и команды получают читаемые имена каталогов вместо GUID-ов.
- В `Конфигурация/` остаются только служебные файлы (`root`, `version`, `versions`, файл
  структуры конфигурации) и модули самой конфигурации.

## Совместимость

Раскладка каталогов изменилась, но **результат сборки — нет**: `-CO` из нового дерева даёт
побайтово тот же контейнер, что и раньше (sha256 `d07244cf…` совпадает со сборкой из старой
раскладки, которую 1С приняла без различий). Привязка при сборке идёт по манифесту, поэтому
деревья, распакованные более старой версией, собираются как прежде.

## Проверено

- `1Cv8_common.cf` — 214 элементов: `-DE` → `-CO` → `-DE`, расхождений нет, списки элементов
  контейнера совпадают; сборка побайтово совпадает с ранее принятой.
- `1Cv8_sp.cf` — 22 элемента: то же.
- В 1С (Конфигуратор → Сравнение): «Различий в конфигурации полученной не найдено».
- Артефакты этого выпуска проверены запуском: linux-бинарник сообщает версию `3.0.48` и
  раскладывает тестовую конфигурацию в новую структуру; в windows-архиве 12 DLL, включая
  `Qt6Core.dll`.

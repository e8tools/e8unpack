# v8Unpack 3.0.55

Справка объектов и HTML-макеты распаковываются файлами `.html`, а ядро распаковки больше не
пишет временных файлов рядом с членами контейнера.

## Справка и HTML-макеты — файлами `.html`

- **Было:** справка объекта и HTML-макет лежали служебными элементами (`<GUID>.1`, `<GUID>.3`):
  внутри структура `{5,<N>,"ru",{#base64:<HTML>}}` — читаемого текста в элементе нет, открыть
  справку в браузере нельзя.
- **Стало:** каждый язык сохраняется отдельным файлом рядом с объектом:

  ```
  <Тип>/<Объект>/Справка/<язык>.html          — справка объекта
  <Тип>/<Объект>/Макеты/<Макет>/<язык>.html   — HTML-макет
  ```

  У самой конфигурации — `Конфигурация/Справка/ru.html`. Содержимое совпадает с тем, что пишет
  «Выгрузить конфигурацию в файлы» (`Ext/Help/ru.html`, `Ext/Template/ru.html`).
- Правку сборка доносит до контейнера: если файл не менялся, в контейнер идут исходные байты
  элемента (сборка получается прежней); если менялся — структура собирается заново из файлов.
- Элементы, лишь похожие на справку, не трогаются: в описаниях форм base64 встречается по другим
  причинам, поэтому нужен признак HTML-содержимого.

## Распаковка: без временных файлов в ядре

- **Было:** порог `SmartLimit` в ядре был выставлен в ноль (опечатка `00 * 1024` вместо ~200 КБ),
  поэтому *каждый* член контейнера, включая стобайтные, проходил через временные файлы
  `.v8unpack.tmp` / `.v8unpack.inf`: запись, чтение, распаковка во второй файл, удаление.
- **Стало:** блоки до 200 КБ разбираются в памяти; через файл по-прежнему проходят блоки крупнее
  200 КБ и результаты распаковки крупнее 64 МБ.
- Измерено на `1Cv8_mods.cf` (403 члена), strace по `openat`: **было 2084 открытия временных
  файлов, стало 0**.

## Совместимость

- Раскладка дерева: справка и HTML-макеты — файлы `.html` вместо служебных элементов. Деревья,
  распакованные прежними версиями, собираются как раньше: элементы просто остаются служебными.
- **`manifest.json` — версия 3.** Дерево, распакованное 3.0.55, нужно собирать 3.0.55 или новее:
  прежние выпуски откажутся (для `.cfe` — с ошибкой) вместо того, чтобы молча собрать элемент
  справки неправильно. Манифесты прежних версий читаются по-прежнему.
- Формат контейнера не менялся. Сборка из неизменённого дерева даёт те же байты, что и 3.0.54.

## Что проверено

- `1Cv8_help.cf` (405 членов: 2 справки + 5 HTML-макетов): все 7 вынесенных файлов совпадают
  побайтово с выгрузкой платформы; сборка из дерева даёт контейнер, равный сборке до правки
  (`c253f04b…`); правка `ru.html` доходит до контейнера; круг `-DE` → `-CO` → `-DE` даёт
  одинаковые деревья.
- Расширение `Расширение1_Тестовое.cfe` (9 членов, справка нового справочника): `ru.html`
  совпадает с выгрузкой (`4ece8753…`), а сборка из дерева со справкой-файлом побайтово равна
  сборке 3.0.54, которая справку не выносила (`2b38c7ac…`).
- Регресс: `1Cv8_mods.cf` — прежний эталон `5f035387…`; расширение `Спецификатор.cfe`
  распаковывается и собирается как в 3.0.53, без расхождений.
- Ядро: сырая распаковка `-U` (807 файлов) совпадает со старой побайтово; дерево и число членов
  не меняются.
- Новая сборка печатает `3.0.55` (`-V`).
